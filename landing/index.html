Also a CLI, a web UI, and a Python library

The same engine powers the desktop app, the local web UI, and the command line. Install it and point it at your own providers.

  • narra "paper.pdf" --format deep-dive --out episode.mp3
  • narra compare "paper.pdf" --voice edge --voice piper
  • narra init-config
  • narra serve
pip install "narra[serve]"
export GEMINI_API_KEY=...        # default writer

narra serve
# open http://127.0.0.1:5372

Local-first, by design

No account. No telemetry. No hosted service. The only network egress is the request to the writer and voice providers you configure; Piper and Kokoro run locally.

Bring your own provider: Ollama locally, an OpenAI-compatible endpoint with your own key, or a cloud key (Gemini, OpenAI). Keys stay in your config, not in a browser.

Run it on your own machine or server and share it: see the self-host & BYOK guide, or host a rate-limited, non-storing instance with --demo (deploy notes).

  • Your source and audio stay on your machine.
  • Session gallery is in memory; Save is explicit.
  • Open source, MIT licensed.
  • Desktop, CLI, and web share one engine.
  • No cloud dependency for the core flow.
